# 酷狗普通版与概念版

设置 → 曲库 → 音乐平台使用下拉菜单，提供网易云、QQ、酷狗普通版和酷狗概念版。

## 接入范围

两版分别提供首页推荐、新歌新碟、歌手目录与筛选、排行榜、歌单分类与分页、歌单/专辑/歌手详情、歌手简介、四类搜索与翻页、搜索建议和热搜、最佳匹配、歌词与逐字歌词、统计与三种评论排序、音频播放、下载音质查询、独立下载地址、MV 与视频 Range 转发。

账号协议包含扫码创建/轮询/确认、账号信息、我喜欢、用户歌单、收藏/取消收藏、创建/删除/重命名歌单和增删歌曲。概念版另提供会员查询、领取记录、手动领取今日权益及可选的每日自动签到。自动签到默认关闭；开启后在启动、登录和窗口恢复焦点时检查，以中国日期和账号去重，成功状态跨重启保存，失败保留错误并冷却十分钟。未模拟听歌或广告。

## 隔离方式

普通版来源为 `kugou`，概念版为 `kugou-lite`。每个 Provider 持有自己的客户端和映射函数，配置、签名、会话、分类缓存均独立，不使用进程全局变量切换版本。

队列、历史、缓存、下载和本地文件的来源标记保留版本。两版账号可以分别保存；切换当前浏览平台不改变队列歌曲来源。概念版的登录确认、个人信息 RSA、播放参数和 Auth 授权链路使用概念版身份。

## 已修复的公共问题

- 酷狗返回的试听流不一定只出现在显式请求试听时：所有返回流都检查 `hash_offset`。
- 音质按实际格式、码率及上游质量字段识别，不能把请求无损后返回的 MP3 标为无损。无法确认时不宣称可用下载音质。
- 概念版部分音频 CDN 仅支持 HTTP，强制替换为 HTTPS 会触发证书域名错误。保留平台原始协议，不关闭 TLS 验证。
- 下载使用独立的 `behavior=download` 请求，不直接拿概念版播放 Auth 作为下载授权。
- 歌单重命名使用云歌单加密协议；删除响应解密失败会报错，不再把无法解析的数据当作成功。
- 账号列表加载和后台复查忽略切换平台后到达的旧结果。
- 私人歌单使用登录态云歌单文件接口，避免公开接口的屏蔽占位项生成 `..` 这样的无效歌曲 ID；历史队列也过滤无效 ID。
- 已登录概念版播放先解析资源权限，选择可用音质对应的 hash、Ogg 资源和最新专辑音频 ID，再完成用户授权、歌曲授权和取流。
- 授权后的 `/tracker/v5/url` 由网关路由，不携带旧接口的 `x-router`；该错误曾导致已登录账号的播放请求返回 HTTP 404。
- 概念版先完成安装级设备初始化：持久化 GUID，按上游算法生成十进制 MID，调用加密的 `r_register_dev` 获取真实 DFID。设备注册完成后才执行登录和业务请求，退出账号和重启不会丢失设备信息。旧实现一直发送 DFID 占位值 `-`，并错误地用其 MD5 作为 MID，是本机此次播放和签到返回 `20028` 的关键漏项。
- 二维码创建、轮询及设备注册不携带旧账号凭证，使用本应用安装身份；登录成功后同时保存绑定的 MID、DFID 以及平台实际返回的 `t1`、`expires`、会员凭据字段。已有登录如果携带完整设备绑定，业务请求沿用该绑定，不能被全局安装身份覆盖。
- 标准音质的概念版“免费听”不能被通用 mediastore 的 VIP 权限状态提前拦截，最终交由正常用户/歌曲授权后的 tracker 判断；其他音质仍按返回资源与权限选择。
- 部分 Ogg 流返回 `bitRate=0` 时，根据实际文件大小与时长计算平均码率，不按请求的音质冒充高品质。
- 上游 `20028` 保留为明确的 403 业务错误，停止自动跳歌；不再误报无版权，也不自动弹出验证窗口。官方返回的验证信息可在设置中主动查看。
- 云歌单的 `20017` 和账号资料的 `20018` 作为认证拒绝返回 401，不能仅凭这些码判定 token 自然到期。其他服务的 `20017` 不统一当成认证失败，避免混淆参数错误。
- 收藏、歌单及歌曲请求返回 401 时，会请求立即复查对应平台，认证拒绝时播放暂停而不继续跳歌。酷狗资料复查失败会保留原凭据及缓存资料，不因单次失败自动删除会话或强制弹出二维码。复查不递归触发自己，网络错误也不触发过期弹窗。此项没有增加所有未选中平台的后台巡检。
- 会话读写会重读其他路由实例保存的新凭据；酷狗资料响应核对请求开始时的会话，旧响应不能覆盖新登录。

## 验证边界

公开接口使用隔离的数据目录真实联网验证，包含音频内容读取和视频 Range；生产 HTTP 检查也使用隔离服务。自动化协议测试覆盖并发凭据隔离、扫码确认、授权链、喜欢和歌单修改、会员请求合并、日期边界、失败响应，以及试听/音质判定。

2026-11-04 对照本机安装的 EchoMusic 2.3.2 的初始化代码与日志后，确认 CoCo 缺少进入业务流程前的设备注册。之前仅执行上游接口模块并沿用 CoCo 的占位设备参数，不能代表完整客户端行为，也不能据此归因于上游或账号。

补齐正常设备注册和标准音质免费听判断后，沿用本机已有的概念版登录账号，在构建后的独立本机 HTTP 服务抽测 8 首歌：全部取流 HTTP 200、音频 Range HTTP 206，实际各读取 4096 字节，均无试听标记。样本包括此前失败的《霜雪千年》《下一秒》，以及《暖一杯茶》《Baby》《有点甜》《冬眠》《还是分开》《错位时空》。独立进程复测复用了持久化设备，没有重新扫码、人工验证或自动解验证。

今日自动签到的真实领取请求已成功，成功回执已持久化。再次通过 HTTP 请求执行自动检查，返回 `already-done`、`attempted=false`，没有重复领取。138 项回归测试、类型检查、Lint 与生产构建通过。

后续收藏/歌单故障诊断中，请求被账号资料接口以 `20018` 拒绝，被云歌单以 `20017` 拒绝。此前直接认定凭据已过期并清理会话的处理不充分：这些响应不能排除设备绑定或请求构造问题。已撤回酷狗复查时直接删除凭据的逻辑。此前那份旧凭据已经被清理，无法再验证其自身是否有效，不能声称已证明 token 自然过期。

对本机 EchoMusic 的同一套已登录会话做只读对照，参考项目和修正后的 CoCo 均可正常读取账号资料及私人歌单。诊断凭据只在内存中使用，没有导入 CoCo 或写入报告，没有重新扫码。145 项回归测试覆盖绑定设备、凭据保留、旧响应与多路由实例会话更新。短时请求成功不代表长期登录稳定性已通过验证；酷狗主动续期尚未完成真实账号验收。

以上是当前账号及样本的验证结果，不代表全曲库和所有会员音质。高音质和实际歌单修改没有进行真实写入验收。

结果见 [公开接口实测](kugou-live-results.json) 与 [生产 HTTP 实测](kugou-http-results.json)。两份结果会记录测试时间、来源、接口及结果，不保存 Cookie、token 或带签名的播放 URL。

## 复测

PowerShell 中运行公开接口验证：

```powershell
$env:COCO_DATA_DIR = "$PWD/node_modules/.cache/kugou-live"
npm run test:kugou:live
```

生产 HTTP 验证需要先 `npm run build`，另开终端启动隔离本机服务：

```powershell
$env:HOSTNAME = '127.0.0.1'
$env:PORT = '3457'
$env:COCO_DATA_DIR = "$PWD/node_modules/.cache/kugou-http"
$env:COCO_SESSION_TOKEN = 'local-integration-test'
node .next/standalone/server.js
```

随后在测试终端运行：

```powershell
$env:COCO_TEST_ORIGIN = 'http://127.0.0.1:3457'
$env:COCO_TEST_TOKEN = 'local-integration-test'
npm run test:kugou:http
```

HTTP 验证包含匿名写操作拒绝检查，仅应指向上述隔离服务，不要指向已登录的日常实例。

上游协议参考 [MakcRe/KuGouMusicApi](https://github.com/MakcRe/KuGouMusicApi)。
